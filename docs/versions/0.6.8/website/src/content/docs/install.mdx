---
title: Install Kelpie
description: Install, update, and verify Kelpie on Linux and macOS.
---

Kelpie ships as a single binary for Linux and macOS.

## Install

Run the installer:

```bash
curl -fsSL https://kelpie.example/install.sh | sh
```

The installer downloads the right release binary for your platform and places it on your PATH.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install kelpie
```

## Install with mise

If you already use mise:

```bash
mise use -g kelpie
```

## Verify

Start Kelpie:

```bash
kelpie
```

If your shell cannot find `kelpie`, restart the terminal or check that the install directory is on your PATH.

## Update

Kelpie checks for new releases and notifies you in the app. You can update manually:

```bash
kelpie update
```

`kelpie update` is for installs managed by Kelpie's own installer. Homebrew, mise, and Nix installs are updated through those package managers instead.

Kelpie uses the stable update channel by default. To opt into preview builds from `master`, set the channel:

```bash
kelpie channel set preview
```

Switch back to stable the same way:

```bash
kelpie channel set stable
```

For direct installs, changing channels also checks that channel and installs its latest binary. If that update fails, run `kelpie update` to retry from the configured channel.

Preview builds are GitHub prereleases published from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

By default, `kelpie update` installs the new binary and leaves compatible running sessions alone. If an update changes Kelpie's client/server protocol, Kelpie asks whether to stop the old server after installing. Stop the old server to use the new version. Stopping exits pane processes. For the default session, run `kelpie server stop`, then run `kelpie` again. For a named session, run `kelpie session stop <name>`, then run `kelpie session attach <name>` again.

To opt into experimental live server handoff for supported running sessions, run:

```bash
kelpie update --handoff
```

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then restart that Kelpie session when you are ready to use the new server. If a running session still uses the old server, stop it with `kelpie server stop` or `kelpie session stop <name>`, then run Kelpie again.

## Install with Nix

If you already use Nix, Kelpie provides a flake that builds Kelpie from source:

```bash
nix run github:kelpie.example/kelpie/v0.x.y
nix build github:kelpie.example/kelpie/v0.x.y
nix profile install github:kelpie.example/kelpie/v0.x.y
```

Replace `v0.x.y` with the latest release tag. You can omit the tag to track `master`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:kelpie.example/kelpie
```

Update through the same Nix workflow you used to install Kelpie. For a profile install, list your profile entries and upgrade the Kelpie entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Kelpie is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update kelpie
```

## Download manually

You can also download a binary from [GitHub releases](https://kelpie.example/source/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `kelpie-linux-x86_64` |
| Linux aarch64 | `kelpie-linux-aarch64` |
| macOS Intel | `kelpie-macos-x86_64` |
| macOS Apple silicon | `kelpie-macos-aarch64` |

Make it executable and move it somewhere on your PATH.

```bash
chmod +x kelpie-linux-x86_64
mv kelpie-linux-x86_64 ~/.local/bin/kelpie
```

## Requirements

Kelpie supports Linux and macOS. Native Windows support is not available yet; use Kelpie inside WSL for now.
