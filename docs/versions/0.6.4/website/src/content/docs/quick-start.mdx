---
title: Quick start
description: Create your first Kelpie workspace and run agents in persistent terminal panes.
---

Start Kelpie from any project directory:

```bash
kelpie
```

Kelpie launches or attaches to your default background session. You do not manage sockets. If you detach, agents keep running.

For the local, SSH, and `kelpie --remote` workflows, see [How to work with Kelpie](/docs/how-to-work/).

## Create a workspace

Press `prefix+shift+n` to create a workspace. A workspace is a project-level container for tabs, panes, and agents.

Give each active project its own workspace. This keeps agent state readable in the sidebar.

## Run an agent

Start your agent in the root pane.

```bash
pi
```

Kelpie detects supported agents automatically. The sidebar shows whether each agent is `working`, `blocked`, `done`, or `idle`.

## Keyboard control

Press `ctrl+b` to enter prefix mode, then press an action key.

Common actions:

| Action | Key |
| --- | --- |
| Split right | `prefix+v` |
| Split down | `prefix+minus` |
| New tab | `prefix+c` |
| Next / previous tab | `prefix+n` / `prefix+p` |
| Workspace navigation | `prefix+w` |
| New workspace | `prefix+shift+n` |
| Detach client | `prefix+q` |

After detaching, run `kelpie` again to reattach to the same session.

## Use the mouse

Kelpie is mouse-native. You can click panes, tabs, workspaces, and agents; drag borders; drag-select text to copy it to your clipboard; double-click a token to copy it directly; and use right-click menus. Copying does not require Ctrl+C.

Ctrl-click opens pane links when your terminal sends the modified click to Kelpie. This works for OSC 8 hyperlinks and visible `http://` or `https://` URLs. The portable terminal-native fallback is Shift-Ctrl-click on Linux or Shift-Cmd-click on macOS.

## Manage named sessions

Named sessions are separate Kelpie server namespaces. Use them when you want fully separate runtime state.

```bash
kelpie session list
kelpie session attach work
kelpie session attach side-project
kelpie session stop work
kelpie session delete side-project
```

Workspaces are usually enough. Use named sessions when you need isolation between sets of panes, sockets, and persistent state.

## Attach from another machine

Run Kelpie where the work lives. If the code and credentials are on a server, either SSH there and run Kelpie like a terminal multiplexer:

```bash
ssh you@server
kelpie
```

Or attach from your local terminal through SSH:

```bash
kelpie --remote workbox
kelpie --remote ssh://you@server:2222
```

For repeat targets, put the host in your SSH config. See [How to work with Kelpie](/docs/how-to-work/) for the full model.
