---
title: Install Kelpie
description: Install, update, and verify Kelpie on Linux, macOS, and Windows.
---

Kelpie publishes stable-channel binaries for Linux, macOS, and Windows. Windows is generally available, with documented platform-specific limitations and ongoing fixes.

## Install

On Linux or macOS, run:

```bash
curl -fsSL https://kelpie.example/install.sh | sh
```

On Windows, run:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://kelpie.example/install.ps1 | iex"
```

If endpoint security blocks that fileless PowerShell command, open Command Prompt and run:

```cmd
curl.exe -fsSLo install.cmd https://kelpie.example/install.cmd && install.cmd && del install.cmd
```

The installer downloads the release binary for your platform and places it on your PATH. New direct installs use the stable update channel. Existing Windows preview installs stay on preview until you switch them with `kelpie channel set stable`. On Windows, PATH points to the active versioned release directory; the installer also updates the `current` and stable `bin` compatibility aliases, so updates do not need to overwrite a running `kelpie.exe`.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install kelpie
```

## Install with mise

If you already use mise:

```bash
mise use -g kelpie
```

If mise reports `kelpie not found in mise tool registry`, update mise and retry. Older mise versions predate the Kelpie registry entry; `mise use -g github:kelpie.example/kelpie` works as a temporary fallback.

## Install with Nix

If you already use Nix, Kelpie provides a flake that builds Kelpie from source:

```bash
nix run github:kelpie.example/kelpie/v0.x.y
nix build github:kelpie.example/kelpie/v0.x.y
nix profile install github:kelpie.example/kelpie/v0.x.y
```

Replace `v0.x.y` with the latest release tag. You can omit the tag to track `master`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:kelpie.example/kelpie
```

Use the same Nix workflow to update Kelpie. For a profile install, list your profile entries and upgrade the Kelpie entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Kelpie is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update kelpie
```

## Download manually

You can also download a binary from [GitHub releases](https://kelpie.example/source/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `kelpie-linux-x86_64` |
| Linux aarch64 | `kelpie-linux-aarch64` |
| macOS Intel | `kelpie-macos-x86_64` |
| macOS Apple silicon | `kelpie-macos-aarch64` |
| Windows x86_64 | `kelpie-windows-x86_64.zip` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x kelpie-linux-x86_64
mv kelpie-linux-x86_64 ~/.local/bin/kelpie
```

### Windows archive

Stable releases and preview prereleases both include `kelpie-windows-x86_64.zip`. The archive contains `kelpie.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `kelpie.exe`.

## Verify

Start Kelpie:

```bash
kelpie
```

If your shell cannot find `kelpie`, restart the terminal or check that the install directory is on your PATH.

## Update

Kelpie checks for new releases and notifies you in the app. You can update manually:

```bash
kelpie update
```

Use `kelpie update` only for installs managed by Kelpie's own installer. Update Homebrew, mise, and Nix installs through those package managers instead.

Direct installs on Linux, macOS, and Windows use the stable update channel by default. To opt into preview builds from `master`, set the channel:

```bash
kelpie channel set preview
```

Switch a direct install back to stable the same way:

```bash
kelpie channel set stable
```

For direct installs, changing channels checks the selected channel and installs its latest binary. If that update fails, run `kelpie update` to retry from the configured channel.

Preview builds are regularly published GitHub prereleases from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

Stable is the recommended channel for normal Windows use. Preview receives fixes sooner but can regress, so opt in only when you want that tradeoff. Existing Windows preview installs remain on preview until you switch them explicitly. If an older preview build rejects `kelpie channel set stable`, run `kelpie update` once on preview, then retry the channel switch.

By default, `kelpie update` installs the new binary and leaves endpoint-generation-1 servers and their pane processes running. Start Kelpie again to reconnect with the updated client. Client-only changes work immediately. A new server-side action stays unavailable until that server is updated and restarted; the client shows a notice instead of disconnecting. Servers from before endpoint generation 1 need one final stop during update.

When it finishes, `kelpie update` lists any running server still on the old version with the command that restarts it, and your saved SSH machines, which run their own Kelpie. Run `kelpie update` on each machine to update it too.

To opt into experimental live server handoff for supported running sessions, run:

```bash
kelpie update --handoff
```

When both servers support agent-status transfer, live handoff preserves hook-reported agent status until the next report arrives. Handoff from an older server can temporarily show a running agent as idle.

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then run Kelpie again to reconnect with the updated client. The compatible old server keeps running. Restart it later with `kelpie server stop` or `kelpie session stop <name>` only when you want server-side changes from the new release.

## Requirements

Stable-channel binaries are available for Linux, macOS, and Windows x86_64. See [Windows support](/docs/windows-beta/) for supported workflows and known limitations. Windows ARM64 runs the x86_64 build under Windows emulation.
