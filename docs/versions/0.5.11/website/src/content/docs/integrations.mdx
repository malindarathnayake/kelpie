---
title: Integrations
description: Install Kelpie integrations for Pi, Claude Code, Codex, OpenCode, and Hermes Agent.
---

Kelpie detects supported agents automatically. Integrations make that detection more precise by reporting semantic state directly to Kelpie.

Use integrations when you want reliable `working`, `blocked`, `idle`, and `done` state from agent hooks or plugins.

## Install integrations

```bash
kelpie integration install pi
kelpie integration install claude
kelpie integration install codex
kelpie integration install opencode
kelpie integration install hermes
```

## Uninstall integrations

```bash
kelpie integration uninstall pi
kelpie integration uninstall claude
kelpie integration uninstall codex
kelpie integration uninstall opencode
kelpie integration uninstall hermes
```

## How Kelpie uses integrations

Kelpie combines three signals:

| Signal | Purpose |
| --- | --- |
| Process detection | Identifies which pane owns which running process. |
| Agent integration events | Reports semantic state such as `working` or `blocked`. |
| Screen heuristics | Fills gaps when hooks are unavailable or incomplete. |

Integrations enrich state reporting. They do not replace process detection.

## Pi

Install the Pi integration:

```bash
kelpie integration install pi
```

Kelpie writes the bundled extension to:

```text
~/.pi/agent/extensions/kelpie-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Kelpie writes to that agent directory instead.

## Claude Code

Install the Claude Code hook:

```bash
kelpie integration install claude
```

The hook reports agent state to the local Kelpie socket when Claude Code exposes hook events.

## Codex

Install the Codex hook:

```bash
kelpie integration install codex
```

Codex state is reported through the same local socket API used by other integrations.

## OpenCode

Install the OpenCode plugin:

```bash
kelpie integration install opencode
```

The plugin reports semantic state while OpenCode runs inside a Kelpie pane.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
kelpie integration install hermes
```

Kelpie writes `~/.hermes/plugins/kelpie-agent-state/` and enables `kelpie-agent-state` in `~/.hermes/config.yaml`. Restart Hermes after installing so the plugin loads.

The plugin reports lifecycle, tool, and approval state while Hermes runs inside a Kelpie pane. Native screen heuristics remain available when the plugin is not installed.

## Custom status labels

Integrations can report a short visual label without changing the semantic state.

For example, an agent can remain semantically `working` while showing `indexing` in the UI.

```bash
kelpie pane report-agent 1-1 \
  --source custom:docs \
  --agent docs-bot \
  --state working \
  --custom-status indexing
```

Custom status is visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
kelpie agent list
```

Read a pane when you need to verify what Kelpie can see:

```bash
kelpie pane read 1-1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Kelpie and that the relevant hook or plugin was installed for the same user account.
